# 公开配置模板

本目录的六份 `config.example.json` 仅用于公开字段结构和安全行为参数，不是部署配置，不含本地账号、应用标识、密钥、白名单地址或定时任务。配置中心运行时读取的是 `config.json`，不会自动使用这些模板。

## 本地文件与发布边界

- 六个子目录的本地 `config.json` 均为私有配置，不得进入 Git 或 GitHub，已有文件必须保留，不能用模板覆盖。
- 公开范围仅限本说明及六份 `config.example.json`。本次不修改忽略规则、不执行 Git、不上传、不运行云函数，也不自动部署。
- 主项目维护者必须在暂存和发布前配置对应的忽略规则并检查暂存清单。忽略规则不能移除已经被 Git 跟踪的文件，也不能清除历史泄露；若曾公开秘密，需单独处理历史并轮换凭据。
- 只有在相应 `config.json` 不存在时，才可由维护者手工参考模板创建该文件，再在本地填写所需配置。不得将填写后的配置回写到公开模板。
- 所有资源继续留在 `uni_modules` 原位置，不得复制到项目根云目录。

## 配置要求

| 模板 | 使用前必须完成的配置 |
| --- | --- |
| `uni-id/config.example.json` | `passwordSecret` 和 `tokenSecret` 必须分别填写独立的、高熵的密码学安全随机秘密，不得留空、复用或使用固定示例字符串。模板只含认证基础字段；需要 OAuth、短信或一键登录时，按实际插件版本在本地补充相应平台和服务配置，所有应用标识、平台密钥、签名私钥及短信模板标识均由维护者自行申请填写。 |
| `uni-sms-co/config.example.json` | `smsKey`、`smsSecret` 必须填写短信服务实际签发的凭据，不得以自造随机字符串替代。还需按业务补齐短信签名、模板及调用权限，完成防刷和额度审核后才能启用。 |
| `uni-open-bridge/config.example.json` | `schedule` 为空，不预置应用或刷新任务；使用前需自行补充所需应用标识、平台凭据和明确的任务配置。按实际调用方配置 `ipWhitelist` 并核对当前版本的访问控制语义；空数组不能被视为拒绝所有访问。 |
| `uni-ad/config.example.json` | 空对象不包含任何广告应用配置。启用前按当前广告插件要求填写应用标识及对应平台签发的密钥，并核对收益回调验签与访问权限。 |
| `uni-stat/config.example.json` | 不预置定时任务，显式关闭调试、Redis、实时统计、分钟统计、页面明细统计、错误检查及日志清理。启用相关功能前应自行配置统计周期、缓存、日志保留策略及所需资源。关闭自动清理不代表无需维护，须另行制定保留与清理策略。 |
| `uni-captcha/config.example.json` | 使用公开的 BMP 行为参数，适配 uni-app x 图形验证码；有效期单位为秒。此模块不需要账号密钥，但必须确认数据库权限、验证码校验流程、场景隔离与调用限流，不能仅靠图形验证码保护短信等付费接口。更多参数见同目录 `config.md`。 |

## 安全注意事项

- 模板中的空字符串刻意表示未配置，不提供固定假密钥；不得将模板直接改名后部署真实服务，也不得自动填充、自动部署。
- 空对象、空数组和局部关闭开关不是全局停用机制。插件可能仍采用默认行为；未使用的服务应在部署和调用入口处保持未启用状态。
- `uni-id` 的时间字段单位为秒，刷新阈值必须小于 token 有效期。密码错误限制不能替代入口限流与权限检查。
- 对已有系统，不得为了采用模板重新生成或覆盖现有秘密。更改密码秘密可能导致已有用户无法登录，更改 token 秘密会使已签发 token 失效；迁移或轮换须按插件流程另行设计。
- 密钥生成应在维护者本地使用密码学安全随机源进行，平台凭据则从对应服务获取。任何真实值都只能写入私有配置或合适的秘密管理设施，不进入公开文档、日志、截图或提交。
